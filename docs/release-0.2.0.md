# Версия 0.2.0 — исправления аудита 08.09.2026

- **Цели:** итог — уникальные визиты с любой выбранной целью, включая `purchase` и любые другие названия. Рекомендация не изменяет ручной выбор. Подробности показывают до 15 выбранных целей; удалённые цели сопровождаются предупреждением.
- **Страницы:** пагинация по 500 строк, до 5 000 страниц за период. При неполной выборке неизвестное значение не подменяется нулём; отчёт предупреждает об ограничении.
- **Старые кнопки:** выбор целей и счётчика привязан к поколению подключения; клавиатуры до обновления требуют открыть новые настройки.
- **Отмена и удаление:** завершение OAuth, обновление токена и отправка отчёта проверяют актуальность подключения. State расходуется атомарно, новый OAuth-запрос отменяет прежний. Удаление не позволяет завершившейся старой работе заново записать события.
- **Очереди:** ограничены размер и параллелизм, повторные отчёты одного пользователя объединяются; управление доступно отдельно. Добавлены квоты, сетевые таймауты, ограниченные повторы и срок сборки отчёта.
- **Роботы:** распознанные Метрикой роботы исключены одинаково из итогов, источников, страниц и целей. Это указано в сообщении.
- **Период:** ручной и автоматический отчёты используют один часовой пояс. «Показать детали» сохраняет исходные даты, длину периода и цели; смена счётчика делает старую кнопку неактивной. Параметры доступны 30 дней; данные Яндекса пересчитываются и могут уточняться.
- **Доступ отозван:** понятное предложение `/connect`, новое подключение даже при существующей записи, приостановка автоматических попыток. Временные сбои повторяются с задержкой, без ежеминутного спама.
- **Работоспособность:** health проверяет оба фоновых цикла; планировщик переживает ошибку базы, завершение основного потока приводит к перезапуску supervisor.
- **Большие аккаунты:** список счётчиков загружается с пагинацией API, счётчики и цели доступны страницами по 20 кнопок.
- **Приоритет:** падение выбранных целей не исчезает из короткого отчёта из-за двух других подсказок.
- **Telegram:** fallback сохраняет целые HTML-теги, сущности и лимит UTF-16; rich HTML проверяется по лимиту 32 КБ. Повторный выбор той же настройки не считается ошибкой.

Новые OAuth-ссылки явно ограничивают `scope=metrika:read`. Профиль и справка описывают изменения и действия для проверки, не обещают автоматически установить причину падения.

Проверки версии: 82 автоматических теста на macOS и Linux / Python 3.12 (расчёты, пагинация, конкурирующие действия, одноразовый OAuth, восстановление после ошибок, реальный локальный HTTP и HTML); ruff. 08.09.2026 проверены миграция копии боевой базы, восстановление с отдельно сохранённым ключом, чтение настоящего API и запуск HTTP. После выкладки `/health` вернул 200, перезапусков и ошибок старта нет; Telegram принял короткий и подробный отчёты владельцу. Настройки подключения и расписания сохранились. Живые данные не включаются в репозиторий.

Ограничения: автоматический тест OAuth использует подставной ответ провайдера; он не заменяет подключение нового аккаунта через экран согласия Яндекса. Доставка через Telegram Bot API проверена; визуальная проверка в клиенте Telegram в этом выпуске недоступна из-за блокировки рабочего компьютера. Счётчик одновременно один; выбрано не больше 15 целей. Неизвестные роботы могут оставаться в данных согласно классификации Яндекса.

Настройка OAuth-приложения: обнаружено ранее включённое дополнительное разрешение `webmaster:hostinfo`. Новые запросы ограничены `metrika:read`; удаление разрешения из самого приложения требует отдельного решения владельца, поскольку Яндекс предупреждает об отзыве всех существующих токенов. Статус верификации сервиса Яндексом остаётся незавершённым; предупреждение пользователю показано перед подключением.
